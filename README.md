# 2048 · 本地网页版

打开 **http://127.0.0.1:2048**。以后双击 `启动游戏.cmd` 即可启动并打开浏览器；`停止服务.cmd` 关闭本项目服务。

项目目录：`E:\项目\游戏\2048-AI`。需要 Node.js 24+，本机已具备；**没有 npm 运行时依赖**。全部资源本地提供，不依赖 CDN。

## 使用

- **开始游戏**：打开首页即可用方向键、WASD 或触屏滑动。方块有滑动、合并和生成动画。首页同时展示玩家排行榜。个人 AI 接管按钮暂不可用，服务端也会拒绝相关请求。
- **AI 实况**：所有人可查看平台 AI 当前棋盘、最近操作、批次进度、累计成绩。详细数据可展开查看最近 20 次测试，以及所选测试的方块达成率和最近 100 局逐局记录。
- **我的记录**：最近 100 局以及全部记录 CSV。数据保存在 `data/2048.sqlite`。
- **账号**：普通用户可注册。首次启动时用 `ADMIN_PASSWORD` 环境变量设置 `admin` 超级管理员的密码；已有本机数据库会保留原密码。超级管理员可启动、暂停、继续和终止平台 AI 测试，准确输入 1–1000 局及 0.25–4 倍思考预算，查看机器状态，并创建或设置权限受限的管理员。普通管理员只有被授予“管理 AI”权限时才能控制平台测试。
- 关闭网页不停止平台 AI；退出服务后再启动，未结束批次从原棋盘暂停恢复。暂停时正在计算的旧结果会丢弃，棋盘及随机出块不变。

标准 4×4 规则：有效移动才生成新块；空格均匀选择，2 的概率 90%、4 的概率 10%；每块每步只合并一次；分数为合并产生的数字之和。达到 2048 或更大数字后继续到无合法移动。不提供撤销、设置棋盘、改分、指定出块接口。

## AI 来源与资源

原仓库：https://github.com/game-difficulty/2048EndgameTablebase

本次检出的 main 提交：`f9d1dba9a42714e32430dfc18e7ac317a6132f0c`（2026-09-24）。完整浅克隆保留在 `upstream/`。

直接复用 `docs/ai_core.js`、`docs/ai_core.wasm`，并从 `docs/worker.js` 原样提取 `CoreAILogic` / `L3Manager` 及其辅助函数。只替换浏览器通信为 Node 工作线程，关闭逐步调试日志。残局表探测、验证、搜索、剪枝、迭代加深及兜底搜索全部使用上游实现；没有另写普通 Expectimax。

引擎 WASM 文件 2,857,054 字节（约 2.9 MB），已包含蒸馏残局数据；不需要解压或生成大型数据库。V8 已在本机编译验证预编译 WASM；无需安装 Emscripten 或编译整套桌面 GUI。重建适配层：`npm run build`。

单个 AI 工作线程复用同一引擎，手动/AI 对局和批次轮流调度。实测服务空闲约 106 MB，独立 AI 单局测试约 103–107 MB RSS；这是采样值，搜索阶段和浏览器会有额外占用。上游 WASM 初始线性内存为 256 MiB，和进程实际驻留内存不是同一指标。完整原仓库约 61 MB，运行资源仅需几 MB 加本地数据库。

未使用 GPU、CUDA、PyTorch、TensorFlow；没有训练模型，也没有生成 free12 或 Mega Tablebase。

原版引擎用 4-bit 棋盘，将大于等于 32768 的数抽象为 `0xf`。游戏和计分始终保存真实值，支持 32768+32768=65536；AI 对更高数值的区分能力沿用上游限制。思考预算倍率以原版 1× 为基准调整搜索时间预算，不保证固定深度或每步严格时间上限。上游公布的成功率不是本机测得的成功率。

## 验证与维护

`npm test`：规则、上游移动交叉比对、用户隔离、管理员权限、平台 AI 访问控制、测试控制和记录接口。

`node scripts/ui-check.mjs`：本机 Chrome + 已有 Playwright 进行真实浏览器测试；检查滑动动画、三页导航、公开 AI 展示、管理员功能和手机布局。结果与截图在 `test-results/`。测试使用临时数据库，不污染正式排行榜。

`scripts/benchmark.mjs`：可选独立完整 AI 对局测试，结果只写入 `test-results/`。按用户要求，交付前不继续长时间跑局。已运行的真实随机对局达到 32768；不据此宣称任何成功率。

数据备份：先停止服务，再复制整个 `data/` 文件夹。账号密码使用随机盐和 scrypt 哈希；会话使用 HttpOnly、SameSite=Strict Cookie。服务默认只监听本机 `127.0.0.1`，这是简单本地用户系统，不是公网竞技防作弊系统。

服务器部署参见 [DEPLOYMENT.md](DEPLOYMENT.md)。运行所需的 `engine/` 文件已包含在仓库中；`upstream/` 是固定版本的原作者源码子模块，克隆时建议使用 `--recurse-submodules`，以便日后运行 `npm run build`。
